# Jolly Muse · 公开网页部署

此仓库仅包含浏览器运行资源，网页入口发布到 https://sugarvei.github.io/jolly-muse-site/ 。完整可编辑工程、原生 Blender 模型和原始渲染资料保存在所有者的独立私有仓库。

`site/` 是 Jolly Muse v3.4.0 的静态网页，保留姿态跟随、触控、暂停、回正、近景和 D4 三维探索。由 GitHub Actions 上传该目录并部署到 GitHub Pages，不安装前端依赖，也不包含模型母版。

v3.4.0 修复 v3.3.0 在颈部混合转头姿态与正面身体造成的虚化、阴影和色差带。现在整个角色只采样同一张完整姿态，颈部不混合另一张纹理；Canvas 2D 回退也不再裁切拼接头身。原始 720×960 图像的前 576 行保持不变；只有已经静止、几何对齐的胸腹部在 576–600 行之间离线统一到公共纹理，600 行以下完全一致。位移仅在静止胸部前收束，不再提前压缩颈部动作。

本版 95 个完整姿态以无损 WebP 编码，生成脚本逐像素校验头颈原样保留、身体一致与无损解码。复现资源：`python tools/build-continuous-neck.py --renders <原始渲染目录>`。脚本复用既有位移图，不改变角色模型或调色。旧版资源和历史实现保留供回溯，当前首页使用 `neck-v34/`。

v3.3.0 将底色、JOLLY 背景字、接触阴影和角色合成在同一个不透明画布中，取消透明角色层下的 CSS 阴影。身体使用固定的原生纹理，转头只调整头颈，避免身体卷绒跟着变形或闪色。Catmull-Rom 采样保留分数像素位置的毛发细节，透明边缘在过滤前预乘，减少暗边；移动和静止使用相同的过滤及清晰度。首次纹理上传与着色器准备完成后才开启交互。导航、按钮和说明仍为可访问的 HTML。

v3.2.0 修复 v3.1.0 多姿态透明叠加造成的双眼、双嘴和轮廓重影。现在每帧只显示一个原生姿态，通过 WebGL 位移映射移动像素，连续跟随目光；不混合不同人脸，也不在停稳后换入另一张细节图。95 个原生姿态及位移图加载完成后常驻，交互过程无需继续请求姿态资源。静止时停止重绘。

图像由原始 PNG 重新生成。默认桌面使用 720×960、手机使用 600×800；浏览器报告内存不超过 4 GB 时自动使用 480×640。精细、均衡、流畅模式分别使用 720×960、600×800、480×640；最高画布像素比为 2。首次姿态资源约 30.5 MiB（无损版本比 v3.3.0 更大，慢网络首屏等待会更长）；加载后转头无需继续下载。角色纹理约为桌面 297 MiB、手机 216 MiB、低内存模式 150 MiB；背景画布另外占用 `画布宽 × 高 × 4` 字节（均不含浏览器其他内存）。不支持 WebGL 的浏览器退回 Canvas 2D 不透明场景，角度变化会更粗，但不叠加不同人脸。

构图根据所有原生姿态的可见边界计算，默认全景保留头顶、耳机、手脚，并避开导航和文字。近景仍支持主动放大。位移是近似的图像变形，不等于重新渲染三维模型；大角度遮挡和毛绒细节仍有近似误差。

头部转动仍会呈现原生渲染中自然的光照与遮挡变化；本版稳定的是身体纹理、画质、采样和场景合成，不宣称每根毛发在所有角度都保持同一像素颜色。原始资源仍是 720×960，不是新增的 4K 渲染。

从零生成图集需要 Pillow、NumPy、OpenCV 和原始 95 张 720×960 PNG：先执行 `python tools/build-warp-atlases.py --renders <原始渲染目录>` 生成位移图，再执行 `python tools/build-continuous-neck.py --renders <原始渲染目录>` 生成当前无损姿态。原始文件名为 `p00_y00.png` 至 `p04_y18.png`。历史 1,241 张姿态文件继续保留，但当前首页不使用其中的光流混合图。更新播放器时同步修改入口脚本版本参数，避免读取旧缓存。

验证：`node --test tests/*.test.mjs`；另在 Chrome 检查连续鼠标跟随、触控、暂停、回正、近景、画质切换、减少动态效果、加载后断网，以及 1440×1000、390×844、320×568、844×390 的中间角度截图。浏览器手机模拟不代表实体手机性能。
